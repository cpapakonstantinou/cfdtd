# Guide to the Documentation

There are three kinds of documentation.

| What | Where | Built with |
|---|---|---|
| The user guide (this site) | Markdown pages under `docs/`, listed in `mkdocs.yml` | `mkdocs build` |
| The key reference | generated from the code | `./fdtd template` |
| The API reference | Doxygen comments in the headers | `make doxygen` |

## Prerequisites

On Ubuntu:

```shell
sudo apt-get install doxygen graphviz
pip install mkdocs python-markdown-math
```

## The user guide

The pages are Markdown; formulas are LaTeX between `$$`. To add a page, create the `.md` file in the
folder that fits and add it to the `nav` of `mkdocs.yml` in the repository root.

```shell
mkdocs build        # writes the site to mkdocs_output/; open mkdocs_output/index.html
mkdocs serve        # or: a local server that rebuilds as you edit
```

Rules that keep the guide true:

- Configuration examples are checked with `./fdtd check` before they go into a page.
- `docs/geometry/Shapes.md` and the figures in `docs/geometry/shapes/` are generated by
  `docs/geometry/make_shape_figures.py`; edit the script, or the key descriptions in
  `src/config/sim_config.cc`, not the page.
- The description of a key lives in one place, the `v.field(...)` line of its section in
  `src/config/sim_config.cc`; `fdtd template` prints it. A page explains how keys work together and
  links to the template for the rest.
- `docs/dev/Roadmap.md` is the record of the work: add to it, do not rewrite its history.

## The API reference

`make doxygen` generates the `Doxyfile` (it is not tracked; the project settings are in the
`Makefile` and `rules.mk`) and writes HTML to `docs/output/html`. File and function comments follow
the Doxygen conventions of the [Style Guide](StyleGuide.md).
